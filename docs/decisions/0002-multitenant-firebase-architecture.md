# 0002 Firebase マルチテナント構成

- 日付: 2026-08-03
- 状態: Accepted
- 関連仕様: テナントと認証
- 置換対象: なし

## 背景

AirGuardV2 は複数の警備会社で利用し、会社ごとの従業員、顧客、現場、勤怠、請求を分離する必要がある。

## 決定

会社データを `Companies/{companyId}` 以下へ配置する構成を基本とし、Firebase Authentication のカスタムクレーム、Firestore/Storage Security Rules、Cloud Functions の検証を組み合わせてテナント境界を守る。

## 理由

データの所属がパスに現れ、クライアントとサーバーの双方で同じ会社境界を検証しやすいため。

## 代替案

- 全会社のデータを同一コレクションへ置きフィールドだけで分離する案: ルールとクエリでテナント条件を漏らす危険が高いため採用しない。
- 会社ごとに Firebase プロジェクトを分ける案: 運用と展開の負荷が大きいため現段階では採用しない。

## 影響

- 利用者: 所属会社または明示されたスーパーユーザー権限の範囲だけを扱う。
- データ: 会社 ID とパスがデータ境界となる。
- 実装: クライアントの表示制御だけに依存せず Rules と Functions でも検証する。
- 確認: 他社 ID を用いた読み書き拒否をユーザーが確認する。
- 運用: カスタムクレーム変更と権限反映の遅延を考慮する。

## 移行

なし。既存構成を文書化した。

## 再検討条件

規制、データ所在地、顧客別暗号鍵、障害分離により会社別 Firebase プロジェクトが必要になった場合。
