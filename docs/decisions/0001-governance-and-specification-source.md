# 0001 仕様管理と正本

- 日付: 2026-08-03
- 状態: Accepted
- 関連仕様: 仕様変更規則
- 置換対象: なし

## 背景

仕様、設計、運用、学習メモが `DEFINITION.md`、`DESIGN.md`、`HISTORY.md`、`definitions/`、実装に分散し、現行仕様と過去の検討を区別しにくかった。

## 決定

`docs/specification.md` を現在確認済み仕様の唯一の正本とする。過去の本文は Git、重要な判断理由は ADR、利用者に見える変更は `CHANGELOG.md` で管理する。一般技術知識は `KNOWLEDGE.md` へ分離する。

作業時は関連文書と実装コードを照合し、指示との相違を変更前にユーザーへ確認する。実装から判明した未記載の恒久仕様は、実装事実と承認済み要件を区別して文書へ反映する。隣接リポジトリは影響範囲の大きいコア基盤として扱い、明示的な対象指定と影響確認なしに変更しない。

## 理由

現行仕様の参照先を一つにしながら、判断理由と履歴を失わず、Codex とユーザーが同じ変更手順を繰り返せるため。

## 代替案

- 機能ごとに独立した正本を置く案: 競合と更新漏れが再発しやすいため採用しない。
- バージョン付き仕様書を複製する案: Git 履歴と役割が重複するため採用しない。

## 影響

- 利用者: 仕様確認先が明確になる。
- データ: 影響なし。
- 実装: 仕様変更時に関連文書も更新する。
- 実装: 文書にない現行挙動をコードから確認した場合も、恒久仕様として必要な記録を更新する。
- 確認: 文書リンク、用語、バージョン、ADR 索引の整合を確認する。
- 運用: 明示的承認後に仕様と実装を同期する。

## 移行

旧文書は直ちに削除せず参考資料として保持し、段階的に現行仕様との差異を解消する。

## 再検討条件

単一仕様書が大きくなり、責任者と参照関係を明確にした分割正本の方が更新漏れを減らせると実証された場合。
