# 0007 プロジェクト専用の専門エージェント構成

- 日付: 2026-08-04
- 状態: Accepted
- 関連仕様: 仕様変更規則、現段階の完了条件
- 関連判断: [0005](0005-multi-agent-and-emulator-testing.md)、[0006](0006-user-prepared-authenticated-browser-testing.md)

## 背景

ADR 0005で主エージェント、リサーチャー、コーダー、テスターによる分担を採用したが、実行に使う `.codex/agents/` が存在せず、文書上の体制とCodexのプロジェクト設定が一致していなかった。また、リサーチャーはコード調査と外部文書調査、テスターはテストと独立レビューを兼任しており、責務と書込み権限の境界が曖昧だった。

AirGuardV2はマルチテナント認証、Firebase Rules、個人・勤怠・請求データ、Stripeを扱い、ユーザー準備済みの認証済みChromeによるUI検証も採用しているため、一般的な基本役に加えて限定的な専門役が必要である。

## 決定

主エージェントを司令塔として維持し、プロジェクト専用エージェントとして次を定義する。

- 基本役: `developer`、`tester`、`code_explorer`、`docs_researcher`、`reviewer`
- 任意役: `ui_tester`、`security_reviewer`

アプリケーションコードの書込みは原則として `developer` に集中させる。`tester` はテスト実行に必要なworkspace-writeを持つが、テストファイルを編集できるのは主エージェントが明示的に委譲した場合だけとし、アプリケーションコードは変更しない。調査、外部文書確認、独立レビュー、UI検証、セキュリティレビューはread-onlyとする。

同時実行上限は4とし、すべてのタスクで全エージェントを起動せず、独立した調査・テスト・レビューだけを必要に応じて並行化する。主エージェントは依頼した全結果を待ち、仕様判断、文書更新、完了判断を統合する。

隣接する `air-guard-v2-schemas` を `.codex/config.toml` の恒常的な書込み対象から外す。隣接リポジトリは、ユーザーが変更対象として明示し、影響を確認した場合だけ別途扱う。

## 理由

調査、実装、テスト、レビューの責務と権限を分離し、自己レビューの偏り、不要な書込み、隣接リポジトリへの影響を抑えながら、AirGuardV2固有のUI・セキュリティリスクを必要時だけ専門的に確認できるため。

## 代替案

- 従来の3役を文書上だけ維持する案: 実行設定がなく、責務と権限の重複も残るため採用しない。
- すべてのエージェントへworkspace-writeを与える案: 調査・レビュー中の不要な変更リスクがあるため採用しない。
- UI・セキュリティ専門役を追加しない案: 認証済みChromeの固有手順と、テナント・決済・機密データのリスクを基本役だけで常に扱うと責務が再び広がるため採用しない。
- リリース操作役を追加する案: デプロイと公開はユーザーの明示的承認が必要で、現在は既存運用文書と主エージェントによる調整で足りるため採用しない。

## 影響

- 利用者: 通常の依頼方法、開発環境、起動手順は変わらない。主エージェントが必要な専門役を選択する。
- データ: 調査・レビュー役はread-onlyであり、外部データを変更しない。Emulatorと認証済みChromeの条件はADR 0005・0006を継承する。
- 実装: `.codex/config.toml` と `.codex/agents/*.toml` を追加・更新する。アプリケーションコードと依存関係は変更しない。
- 確認: 各役は根拠、実施内容、未確認範囲を主エージェントへ返し、主エージェントが統合する。
- 運用: ユーザーが起動したプロセスは停止せず、Codexまたはテスターが起動した検証プロセスだけを終了時に片付ける。

## 移行

`AGENTS.md` と `INITIAL_PROMPT.md` の役割名とルーティングを更新し、READMEへ `.codex` の文書地図を追加する。既存仕様、ADR、マニュアル、一般技術知識、ユーザーの未コミット差分は保持する。

## 再検討条件

エージェントの利用実績から役割の重複や不足が確認された場合、同時実行上限が作業品質を損なう場合、またはCodexのプロジェクトエージェント設定仕様が変更された場合。
