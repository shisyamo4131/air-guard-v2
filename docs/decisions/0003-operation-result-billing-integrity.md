# 0003 稼働実績と請求の整合性

- 日付: 2026-08-03
- 最終更新日: 2026-08-13
- 状態: Accepted
- 関連仕様: 稼働実績、請求・税・丸め
- 置換対象: なし

## 背景

稼働実績は勤怠と請求の双方の元データであり、取極め未設定、締日未設定、確定後の編集によって不整合が生じ得る。

## 決定

取極めがない稼働実績も業務記録として保存できるが、原則として理由付きの無効状態にし、請求へ反映しない。売上へ連動しない実績だけ明示的な許可で取極めなしを有効とする。

`OperationResult.isLocked` は請求確定、承認済み、またはドキュメント全体の変更禁止を表さない。請求担当者が調整した請求内容を後続の管制側更新による上書きから保護するため、管制側の稼働実績編集と削除を止める。ロック中も請求担当者による請求項目の編集を許可する。

認可は曖昧な管理者区分ではなく機能権限で判定する。`operation-results:write` はロックされていない稼働実績の編集・削除、`operation-billings:write` は請求項目の編集とロック設定・解除を担う。追加の承認や理由入力は要求せず、最終更新者と最終更新日時は既存の `uid` と `updatedAt` へ自動記録する。変更前後の永続履歴や履歴用コレクションは現時点では追加しない。

## 理由

現場実績の記録を失わずに未確定単価が請求へ混入することを防ぎ、請求担当者の調整を管制側の後続更新から守りながら、承認待ちによる業務停滞を避けるため。

## 代替案

- 取極め未設定時に実績作成を全面拒否する案: 現場記録を後回しにし、欠落を招くため採用しない。
- 未確定単価をゼロ円で自動請求する案: 請求漏れを見落としやすいため採用しない。

## 影響

- 利用者: 無効理由を解消してから請求へ反映する。
- データ: 実績、取極め、請求、勤怠の参照関係を保つ。
- 実装: 非同期更新では重複実行とロックを考慮し、Rulesを含む全書込み経路で機能権限とロック境界を強制する。
- 確認: 取極めなし、許可あり、管制側編集、請求側編集、ロック設定・解除の各ケースをユーザーが確認する。
- 運用: 未解消の無効実績を把握できる必要がある。

## 移行

既存データの移行は不要。2026-08-13に、全面的な更新禁止と読める記述を管制側編集ロックの契約へ訂正した。実装とRulesの修正は別途承認・検証する。

## 再検討条件

取極め以外の単価確定フロー、承認ワークフロー、請求版管理を導入する場合。
