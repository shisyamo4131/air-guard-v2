# 0005 マルチエージェント体制とEmulator検証

- 日付: 2026-08-04
- 状態: Accepted
- 関連仕様: 現段階の完了条件
- 置換対象: [0004](0004-codex-verification-boundary.md)

## 背景

調査、実装、レビューを分離して品質を高めるため、主エージェントが複数の専門サブエージェントを統括する体制が必要になった。また、Codex環境からFirebase EmulatorとNuxtローカルサーバーを起動できることが確認され、隔離された範囲で検証を担当できるようになった。

## 決定

主エージェントを司令塔とし、リサーチャー、コーダー、テスターへ必要なサブタスクを分担する。テスターはユーザーが明示的に許可した場合、`saved-data`を読み込んだFirebase Emulatorとloopback限定のローカルサーバーで単体・結合テストを実行できる。

Emulator起動時の警告、Functionsの外部API呼出し、通知・メール・Stripeなどを確認し、外部作用を排除できない検証は実行しない。認証済み画面に専用アカウントが必要な場合はユーザーへ作成を依頼する。

## 理由

調査・実装・検証の観点を分離しつつ、ユーザーの環境やリモートデータへ影響しない範囲で早期に回帰を検出できるため。

## 代替案

- すべてを主エージェントだけで処理する案: 独立レビューと並行調査の利点が得られないため採用しない。
- Codexによる全環境テストを許可する案: 外部作用と認証情報のリスクが大きいため採用しない。
- 引き続きCodexのテストを全面禁止する案: 利用可能なローカル隔離環境を活用できないため置き換える。

## 影響

- 利用者: 最終的な試験運用上の確認を担当し、必要に応じてEmulator専用アカウントを用意する。
- データ: `saved-data`は読込元とし、明示的な指示なしにテスト結果で上書きしない。
- 実装: 主エージェントが担当範囲を分離し、コード差分と報告を統合する。
- 確認: テスターはコマンド、環境、結果、未確認範囲を報告する。
- 運用: Emulatorとローカルサーバーはテスト後に停止し、一時ログを残さない。

## 移行

`AGENTS.md` と `INITIAL_PROMPT.md` をマルチエージェント体制へ変更し、Emulator検証手順を `docs/operations.md` へ追加する。ADR 0004をSupersededとする。

## 再検討条件

CI環境が整備された場合、ブラウザ自動操作の利用環境が変わった場合、またはEmulatorでも外部作用を十分に隔離できないことが判明した場合。
