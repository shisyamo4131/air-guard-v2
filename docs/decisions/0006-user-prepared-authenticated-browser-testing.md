# 0006 ユーザー準備済み認証画面によるUI検証

- 日付: 2026-08-04
- 状態: Accepted
- 関連仕様: 現段階の完了条件
- 関連判断: [0005](0005-multi-agent-and-emulator-testing.md)

## 背景

現在のChrome操作レイヤーではAuth Emulatorへの直接接続が遮断され、Codex単独でサインインを自動化できない。一方、ユーザーがEmulator、ローカルサーバー、Chromeを起動してサインインした既存タブは、Codexが引き継いで認証後画面を読み取り、操作できることを確認した。

## 決定

Codexが認証後のUIテストを行う場合、ユーザーがEmulator、ローカルサーバー、Chromeを起動し、Emulator専用アカウントでサインインした画面を準備する。Codexはその既存タブを引き継いでテストする。

CodexはSPAローディングテンプレートを即時エラーと判断せず、遷移完了または明確なタイムアウトまで待機する。データ変更を伴う操作は、ユーザーがテスト内容として明示的に許可した範囲だけで行う。ユーザーが起動したプロセスはCodexが停止しない。

## 理由

ユーザーの通常の環境構築と起動手順を変更せず、追加のプロキシ、E2E依存関係、危険なブラウザ起動オプションを導入せずに、認証後のUI検証を実施できるため。

## 代替案

- 同一オリジンのローカルプロキシを追加する案: 専用設定と保守対象が増え、通常環境との差異が生じるため採用しない。
- 専用E2Eブラウザとスクリプトを追加する案: プロジェクトの依存関係と環境を変更するため採用しない。
- Chromeのセキュリティ機構やsandboxを無効化する案: 安全性を低下させるため採用しない。
- Codexによる認証後UIテストを行わない案: 既存タブを安全に引き継げることが確認できたため採用しない。

## 影響

- 利用者: UIテスト前にローカル環境を起動し、サインイン済みの対象画面を準備する。
- データ: テストで許可されたEmulatorデータだけが操作対象となる。
- 実装: アプリケーションコード、依存関係、通常の起動手順は変更しない。
- 確認: Codexは画面遷移を待機し、操作結果、エラー、未確認範囲を報告する。
- 運用: ユーザーが起動したEmulator、ローカルサーバー、Chromeの終了もユーザーが担当する。

## 移行

`AGENTS.md`、`docs/specification.md`、`docs/operations.md`へ条件を追記する。環境変更やデータ移行はない。

## 再検討条件

Chrome操作レイヤーからAuth Emulatorへ安全に直接接続できるようになった場合、または隔離された標準E2E環境の導入をユーザーが承認した場合。
