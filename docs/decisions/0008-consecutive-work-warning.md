# 0008 配置管理の連勤判定と注意喚起

- 日付: 2026-08-04
- 状態: Accepted
- 関連仕様: 稼働予定・配置通知・上下番
- 置換対象: なし

## 背景

配置管理画面は表示期間内の現場稼働予定だけを取得しているため、同日の日勤・夜勤および日をまたぐ夜勤・翌日日勤の連続配置を利用者へ示せない。特に表示期間の初日と最終日は、隣接日の予定が取得範囲外となる。

## 決定

- 連勤判定は従業員だけを対象とし、外注先は対象外とする。
- 同一従業員が同一日付の `DAY` と `NIGHT` の両方に配置されている場合を連勤とする。
- 同一従業員がある日の `NIGHT` と翌日の `DAY` の両方に配置されている場合を連勤とする。
- 判定用の現場稼働予定は、画面の表示期間に対して前後1日を加えた期間で取得する。前後1日の予定は判定だけに使用し、画面の表示期間は変更しない。
- 連勤は配置を拒否する制約ではなく注意喚起とする。連勤関係を構成する双方の配置タグに警告アイコンを表示し、ツールチップでそれぞれの配置から見た判定理由を示す。

## 理由

- 外注先の識別子は会社を表し、異なる予定間で同一人物を安定して識別できるとは限らないため、外注先を含めると誤判定のおそれがある。
- 表示期間の前後1日だけを追加取得すれば、定義された連勤条件に必要な境界データを過不足なく参照できる。
- 既存のタグ全体の強調表示は重複ドロップの一時通知に使われているため、専用の警告アイコンと理由表示を用いる方が意味を区別できる。

## 代替案

- 表示期間内だけで判定する案: 期間境界で判定漏れが生じるため採用しない。
- 外注先も対象にする案: 作業員個人を予定間で一意に識別できないため採用しない。
- 連勤時に配置保存を拒否する案: 今回の目的は利用者への通知であり、業務上必要な配置まで禁止するため採用しない。
- 既存のタグ全体の強調表示を使う案: 重複ドロップ通知と意味が競合するため採用しない。

## 影響

- 利用者: 配置管理画面で連勤の可能性と理由を確認できるようになる。
- データ: Firestoreへ保存する項目や既存ドキュメントの変更はない。
- 読み取り: 現場稼働予定の購読範囲が表示期間の前後1日分広がる。
- UI: 連勤関係を構成する双方の配置タグへ警告アイコンと理由ツールチップを追加する。
- 互換性: 既存データの移行は不要で、配置の保存可否も変更しない。

## 移行

なし。

## 再検討条件

- 外注作業員を予定間で一意に識別できるデータモデルを導入した場合。
- 連勤を注意喚起ではなく配置制約として扱う業務規則が承認された場合。
- 判定対象を勤務区分ではなく実際の開始・終了日時に基づける必要が生じた場合。
