# 0009 配置管理の日別稼働・配置・状態集計

- 日付: 2026-08-05
- 状態: Superseded
- 関連仕様: 稼働予定・配置通知・上下番
- 置換対象: [0010 配置通知を優先する作業員実効値と人員集計](0010-notification-preferred-effective-worker-values.md)

## 背景

配置管理画面では現場稼働予定ごとの必要人数と過不足を確認できるが、日全体の必要人数と配置人数、および配置された作業員の状態別件数を一覧で確認できない。利用者が、配置通知を作成していない仮配置や、日全体の人員不足・超過を見落としにくくする必要がある。

## 決定

- 日付ヘッダーに、その日の全現場稼働予定を合計した稼働数、配置人数、過不足を表示する。
- 稼働数は `SiteOperationSchedule.requiredPersonnel` の合計とする。
- 配置人数は既存の予定単位の過不足判定と同じ `SiteOperationSchedule.assignedPersonnelCount` の合計とし、OJT を含めない。
- 日付列の固定フッターに、配置明細の状態別件数を表示する。
- 配置通知が存在せず、通知済みフラグもない配置明細を「仮配置」、通知状態が `ARRANGED`、`CONFIRMED`、`ARRIVED`、`LEAVED` の配置明細を、それぞれ「配置済」「確認済」「上番済」「下番済」とする。
- 配置通知と通知済みフラグが一致しない場合、または既知の状態へ分類できない配置通知は「要確認」として表示する。
- 状態別件数は配置明細単位とし、同一作業員が同日に複数の予定へ配置されている場合はそれぞれ数える。OJT も状態別件数には含める。
- 表示期間内ですでに購読している現場稼働予定と配置通知から画面内で集計し、保存項目や追加の Firestore 読み取りは導入しない。

## 理由

- 日全体の必要人数と配置人数を日付の近くへ表示することで、横スクロールする表でも対象日と過不足の対応を把握しやすい。
- 作業員の状態を固定フッターへ分離することで、主要な充足情報をヘッダーで優先しつつ、縦スクロール中も状態内訳を確認できる。
- 既存の `assignedPersonnelCount` を使用すれば、現場稼働予定カードの過不足表示と日別集計の判定基準が一致する。
- 状態別件数を一意な人物数ではなく配置明細数とすることで、必要人数が発生する勤務枠との対応を保てる。

## 代替案

- すべての集計を固定フッターへ表示する案: 日全体の稼働数と配置人数を日付から離さず確認したい要件に合わないため採用しない。
- `workers.length` を配置人数とする案: OJT と外注人数を既存の過不足判定と同じ基準で扱えないため採用しない。
- `CONFIRMED` を「配置済」へ合算する案: 作業員による確認前後を区別できなくなるため採用しない。
- 集計結果を Firestore に保存する案: 既存の購読データから導出でき、同期処理と不整合のリスクが増えるため採用しない。

## 影響

- 利用者: 日別の人員過不足、仮配置、配置通知確認、上下番の進捗を配置管理画面から確認できる。
- データ: Firestore の保存項目および既存ドキュメントを変更しない。
- 読み取り: 追加の Firestore 読み取りは発生しない。
- UI: 日付ヘッダーと固定フッターの表示量が増える。
- 互換性: データ移行および設定変更は不要。

## 移行

なし。

## 再検討条件

- OJT を必要人数の充足へ含める業務規則へ変更する場合。
- 外注先の `amount` または配置通知の単位を変更する場合。
- 日別集計を他画面、帳票、またはサーバー処理でも共有する場合。
