# 0036 終了済み現場を表示順へ残す判断

- 日付: 2026-08-31
- 状態: Accepted
- 関連仕様: Company設定とtenant lifecycle
- 関連ロードマップ: [Company部分更新](../roadmaps/company-partial-updates.md)
- 関連判断: [0035](0035-company-display-order-update-boundary.md)
- 置換範囲: ADR 0035の「非active Siteを表示から除外する」判断だけを置き換える。その他の表示順更新・権限・競合・保存境界は維持する。

## 背景

当初は終了済みを含む非active Siteを表示順編集から除外した。しかし、現場を終了済みにした後でも突発的に稼働予定が発生する業務がある。その場合に終了済み現場を並べ替えられないと、配置管理・稼働予定の表示順を利用者が管理できない。

削除済み現場はSite document自体が存在しないため、表示順編集へ残す必要はない。

## 決定

- Site documentが存在する限り、`ACTIVE`、`TERMINATED`、その他の状態にかかわらず表示順編集へ残す。
- Site documentが存在しない参照だけを削除済みとして表示から除外する。
- 存在しない参照は自動保存せず、利用者が次に明示保存した時だけorderから除去する。
- Site取得に失敗した場合は削除済みと推測せず、編集中のdraftを維持して保存を止める。

## 理由

終了済みは業務状態であり、削除済みとは異なる。将来の稼働予定が発生し得る既存現場を表示順から外さず、documentの不存在だけを削除の根拠にすることで、突発運用と誤削除防止の両方を満たせる。

## 代替案

- `ACTIVE`だけを残す案: 終了後の突発的な稼働予定を並べ替えられないため採用しない。
- `ACTIVE`と`TERMINATED`だけを列挙する案: 将来追加される状態や一時状態を誤って削除済み扱いするため採用しない。
- 不存在参照を画面表示時に自動保存して除去する案: 画面を開いただけでdataを変更するため採用しない。

## 影響

- 配置管理と稼働予定の表示順編集に、終了済みを含む既存現場が表示される。
- 削除済み現場の旧参照は表示されず、次回の明示保存でだけ除去される。
- Callable、Rules、保存形式、権限、Company document構造、既存dataは変更しない。
- Dev、Prod、remote/data、deploy、migration、Schemas/Admin SDKは変更しない。

## Rollback

本変更のlocal commitをrevertし、画面処理、回帰test、文書を一体で戻す。data migrationと自動cleanup writeがないためdata rollbackは不要である。

## 検証

- ACTIVE、TERMINATED、その他の状態を持つ既存Siteがdraftと保存payloadに残る。
- 存在しないSiteだけがdraftから除外され、画面を開いただけでは保存されず、明示保存時だけpayloadから除去される。
- Site取得失敗時はdraftを維持し、操作を止め、保存eventを発生させない。
- 表示順の対象test 15件と全domain test 722件を成功させる。
- 利用者の実際の環境で終了済み現場の表示を最終確認する。確認用dataを作れない場合は、自動test結果と利用者による業務契約の確認を分けて記録する。

## 再検討条件

終了済み現場の表示が通常運用を妨げる具体的な事例が確認された場合、または削除済みをdocument不存在以外で表す正式な保存仕様を採用する場合。
