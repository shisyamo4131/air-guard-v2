# 0010 配置通知を優先する作業員実効値と人員集計

- 日付: 2026-08-05
- 状態: Accepted
- 関連仕様: 稼働予定・配置通知・上下番
- 置換対象: [0009 配置管理の日別稼働・配置・状態集計](0009-arrangement-daily-summary.md)

## 背景

配置予定の作業員明細と配置通知は、OJT、資格、勤務時間など同種の業務プロパティを持つ。利用者は画面上でどちらのドキュメントを編集しているかを意識せず、配置通知上の編集結果は稼働実績生成で予定より優先される。一方、配置管理の日別配置人数と現場稼働予定カードの過不足は予定明細の OJT だけを参照するため、タグ表示や将来の実績と異なる判定になり得る。

## 決定

- 日付ヘッダーに、その日の全現場稼働予定を合計した稼働数、配置人数、過不足を表示する。稼働数は `SiteOperationSchedule.requiredPersonnel` の合計とする。
- 日付列の固定フッターに、配置明細の状態別件数を表示する。配置通知が存在せず通知済みフラグもない配置明細を「仮配置」、通知状態が `ARRANGED`、`CONFIRMED`、`ARRIVED`、`LEAVED` の配置明細をそれぞれ「配置済」「確認済」「上番済」「下番済」とし、通知とフラグの不整合または未知状態を「要確認」とする。
- 状態別件数は配置明細単位とし、同一作業員が同日に複数の予定へ配置されている場合はそれぞれ数える。OJT も状態別件数には含める。
- 配置管理で作業員明細と配置通知が共有する業務プロパティの実効値を求める場合、配置通知があれば配置通知の値を優先し、配置通知がない場合だけ予定作業員明細の値を使用する。
- 真偽値の `false` は配置通知による明示的な上書きとして扱い、論理和ではなく nullish fallback または配置通知の存在判定で解決する。
- 配置作業員タグは実効 OJT 状態を表示し、OJT が配置人数に含まれないことを利用者が確認できるようにする。
- 日別配置人数は、作業員ごとの実効 OJT 状態を解決し、非 OJT の従業員は1人、非 OJT の外注先は明細の `amount` 人として集計する。
- 現場稼働予定カードの人員過不足も、日別配置人数と同じ実効 OJT 状態による配置人数で判定する。
- 固定フッターの状態別件数は従来どおり配置明細単位で数え、OJT も含める。
- 既存の表示期間内の配置予定と配置通知を使用し、追加の Firestore 読み取りや保存項目は導入しない。
- 配置通知モデルで保存フィールドが欠落した真偽値は既定値 `false` に正規化されるため、古い配置通知に OJT または資格フィールドが存在しない場合も通知側の `false` として扱う。これは稼働実績生成が既に採用している通知優先の解釈と一致する。

## 理由

- 利用者が編集対象ドキュメントを意識しなくても、配置通知上の最終編集結果を一貫して確認できる。
- `false` を有効な値として扱うことで、配置通知側で OJT や資格を外した操作を失わない。
- 日付ヘッダーと現場カードで同じ配置人数を使い、同一画面内の過不足表示の矛盾を防ぐ。
- 稼働実績生成が配置通知を優先する既存挙動と配置管理の表示を一致させる。

## 代替案

- 論理和で `notification.isOjt || worker.isOjt` とする案: 配置通知側の明示的な `false` が失われるため採用しない。
- 日別配置人数だけを通知優先にする案: 現場カードの過不足と数値が一致しなくなるため採用しない。
- 予定作業員明細へ配置通知の編集値を逆同期する案: 予定と通知・実績の履歴的役割を混同し、保存処理の影響が大きいため採用しない。
- スキーマパッケージの `assignedPersonnelCount` を変更する案: 配置通知を保持しない他モデルにも影響し、隣接リポジトリの互換性リスクがあるため採用しない。

## 影響

- 利用者: 配置通知上で編集した OJT 状態が、タグ、日別配置人数、現場カードの過不足へ反映される。
- データ: Firestore の保存項目と既存ドキュメントを変更しない。
- 読み取り: 追加の Firestore 読み取りは発生しない。
- UI: OJT 表示が作業員タグへ追加される。
- 互換性: データ移行と設定変更は不要。配置通知と予定明細の OJT が異なる既存データでは、表示上の配置人数と過不足が従来から変わる。
- 既存データ: 古い配置通知で OJT または資格フィールドが欠落している場合、モデル既定値の `false` を実効値とする。予定値へのフォールバックは行わない。

## 移行

なし。

## 再検討条件

- 配置通知と予定作業員明細の責務または同期方針を変更する場合。
- 配置通知に存在しない古い OJT フィールドと、明示的な `false` を区別する必要が生じた場合。
- 通知優先の実効値解決を配置管理以外の複数画面で共通利用する場合。
